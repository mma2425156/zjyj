# Word 批注制作与核验

## 操作原则

- 先确认文件的实际格式并复制原件到新文件；不得通过改扩展名假装完成 `.doc` 与 `.docx` 转换。保存前检查目标文件是否已存在、是否被占用以及输入是否发生并发改动。
- 使用支持真实批注、已有批注及其作者的 Word/WPS 或可靠的文档工具。优先保持原格式；确需转换时在副本上转换，核对复杂表格、公式、图片、分页及批注兼容性，并向用户说明。工具能力不足时保留审查底稿并说明限制。
- 在具体文字、数字或表格位置设置锚点；可选中能准确定位问题的短范围。表格、空段落、图形或跨章节的问题要确保锚点仍易于找到，不能为实现批注破坏正文或表格结构。
- 新增评论的作者根据本项目评审单位和用户要求设置，国仕项目为 `GS`；先读取现有作者、批注和回复，再添加新批注，不覆盖其他作者或批注。不能因软件用户名或默认作者把新增批注标成个人姓名或其他单位。
- 用程序操作时确保不执行文档宏、不修改用户的全局作者设置；若只能修改应用的用户设置，须保存并恢复原设置，使用隔离应用实例并核对，不能影响正在使用的文档。关闭输入时不保存任何变动。

## 本机已验证的可选途径

在本机独立 WPS 文字自动化实例中，使用合成测试分别保存 `.doc` 和 `.docx`，均验证了：新增 `Comments.Add(范围, 内容)` 后设置该条批注的 `Author = 'GS'`，关闭并重新只读打开，批注数、作者、文字和所选锚点一致。此结果只证明该环境和简单测试可用，不保证复杂报告、其他版本 WPS 或 Word 完全兼容；实际交付仍须逐项核验。禁止将示例测试覆盖项目文件。

操作思路：只读打开源文档确认版本及已有批注；在副本上打开，定位范围并逐条新增；逐条设置和检查本次批注作者；保存关闭，再只读重开校验；最后以 WPS/Word 检查代表性页面及批注显示。涉及 `.doc` 时应使用真正支持该格式的应用，不依赖将文件名改为 `.docx`。

对于 `.docx`，使用 Open XML 的实现还须处理批注部分、关联关系及范围标记：同一条批注的标识、起止范围和正文引用必须匹配，标识不能与已有批注冲突；还要保留已有批注、回复及扩展结构。直接改 XML 有兼容性风险，不能仅检查压缩包内容就声称 Word/WPS 显示正常。

## 验收

1. 比较副本和源文件：正文、表格、图片等主要内容未被无意改写；原有批注、作者和回复仍在；新增数量与底稿一致。
2. 重开文档检查新增批注逐条作者、文字及锚点；核对批注中引用的数值、章节、逻辑和专家意见。发现空白、重复或锚点错误时仅修正本次新增内容。
3. 在实际可用的 Word 或 WPS 中查看多个有代表性的正文和表格页面、批注窗格、特殊对象以及前后分页；不能做完整逐页检查时如实说明。必要时抽查或核对其他软件兼容性，不能把单一环境的显示当成所有环境均正常。
4. 检查文件名、目录及版本，确认原件未被覆盖。发现来源被并发修改、文件占用、保存失败或无法验证批注时停止覆盖或交付，查明并处理后再继续。
